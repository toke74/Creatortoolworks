# Standard Tool Page Specification

## Purpose
Every tool page follows one consistent information architecture while allowing the workspace to fit the task.

## Required page anatomy
1. Breadcrumbs (when helpful).
2. H1 tool name.
3. One-sentence value proposition.
4. Tool workspace.
5. Result/output area.
6. Concise “How to use” guidance.
7. Methodology/limitations if the output is a score, estimate, or platform-rule check.
8. Current source note when relying on changeable platform rules.
9. Examples when examples materially reduce confusion.
10. Related tools.
11. Additional explanation only when it helps the task.

## Workspace requirements
- Input labels and constraints visible before submission where possible.
- Validation close to the relevant field.
- Primary action is unambiguous.
- Reset does not look like primary action.
- Copy/download action appears only when there is a result.
- Never require an ad interaction to reveal a result.

## URL pattern
Recommended:
`/youtube-tools/<tool-slug>`

Category indexes:
`/youtube-tools/<category-slug>` only if they are genuinely useful browsing pages.

## Metadata
- Unique title.
- Unique meta description.
- Canonical URL.
- Share image strategy where useful.
- No index for drafts/empty scaffolds.

## Content rule
No fixed word-count requirement. Provide the minimum amount of original explanation necessary for confident use, plus methodology/limitations when relevant.

## Related tools
Select by next likely creator task, not keyword similarity alone. Aim for 3–6 high-quality links rather than dozens.
